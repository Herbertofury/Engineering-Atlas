# Contribution rules

1. State the exact problem, platform, versions, workload and acceptance criteria before choosing a solution.
2. Prefer official documentation, upstream source, release notes and original papers. Record publication/version separately from the date you checked it.
3. Label source facts, your hypothesis, measured results and production acceptance separately.
4. Include a rejected alternative and the tradeoff that matters. Do not rank by popularity or novelty alone.
5. Keep correctness, security and required feature coverage fixed across performance comparisons.
6. Preserve failing evidence. A retry is a new result, not permission to erase the first failure.
7. Link evidence only after checking it is appropriate to publish. Exclude credentials, raw user logs, personal paths, proprietary assets and unapproved third-party code.
8. A documentation change does not authorize upgrades or changes in another project. Recheck that project's target and permissions.
9. Keep source and generated documentation consistent. Run the local checks before publication.
10. Summarize the real user-visible outcome, not merely the number of patches or warmed caches.

No blanket license is granted to third-party material by including a link. Use brief original summaries, credit sources, and check each asset's license before reuse.

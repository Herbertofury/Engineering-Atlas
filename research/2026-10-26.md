# Research review · 2026-10-26

**Scope:** starter research pass. Facts below are primary-documented; no comparative application benchmark is claimed.

## Useful current findings

- Electron 45 stable was announced on October 21, 2026. The release describes startup/native-call changes and a tracing migration. Compare the exact prerelease/stable delta before changing an installed product. [E03](../docs/sources.md#e03)[E04](../docs/sources.md#e04)
- Current Node documentation separates CPU-worker use from efficient built-in async IO. Worker CPU/heap profiling APIs are version-dependent; check the installed Node runtime rather than assuming latest-documentation availability. [N01](../docs/sources.md#n01)
- Current Tokio filesystem documentation recommends batching blocking filesystem work to avoid excessive task-transition overhead. [R02](../docs/sources.md#r02)
- Rust's Windows DirEntry metadata/type behavior can avoid redundant OS lookups, but enumeration information does not replace security-sensitive revalidation before deferred access. [R01](../docs/sources.md#r01)
- Tauri's process model and Electron's guidance both support explicit work/privilege boundaries. Framework choice still needs a representative measured slice. [T01](../docs/sources.md#t01)[E01](../docs/sources.md#e01)
- Modern Fabric/NeoForge documentation targets a different Java/game lane from pinned Forge 1.20.1. Latest is not a compatibility migration plan. [M01](../docs/sources.md#m01)[M02](../docs/sources.md#m02)[M03](../docs/sources.md#m03)
- OWASP ASVS provides versioned verification requirements; application-specific evidence remains necessary. [SEC01](../docs/sources.md#sec01)

## Proposed experiments

1. Serial versus bounded parallel file inspection; sweep 4/8/16/32/64.
2. Repeated owner matching versus a per-scan immutable index.
3. Small-task dispatch versus bounded batches, retaining fresh hashes and all path checks.
4. Installed desktop launch and input under concurrent background updates.
5. Same engine/runtime, same corpus: compare first-result and verified-completion latency separately.

Record complete-result equivalence before discussing speedup. Small cache wins may support the outcome, but do not substitute for a substantial end-to-end improvement when that is the request.
